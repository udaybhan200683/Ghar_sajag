3. The shipped static PWA reads the local API snapshot; focused Chromium asserts
   caregiver timeline/identity/chronology, door status, freshness, incident and
   post-reload rendering.

## Opt-in physical HIL runner implementation

`make validation-board-hil` and `make validation-motion-hil` are separate
operator-invoked targets and are explicitly outside Node, Hub, contract, fast
and release software execution. They reuse the existing 99-case
`PHYSICAL_HIL_CATALOGUE.csv` and the GS-114 attempt06 fixture identities and
image hashes. Before an observation run they require exact by-id interfaces,
read-only udev serial identity, supplied matching image artifact hashes, an
operator token and an explicit `--observe`/`--run` flag. They never flash,
reset, enroll, inject, write UART commands, interrupt power or alter storage.
Redaction is applied before serial logs are saved; a nonempty prior evidence
directory cannot be overwritten. Real AM312 acceptance rejects `INJECT_MOTION`
and requires GPIO4 wake, runtime restore, one C3 EventKey, matching S3 key,
authenticated application Durable ACK and C3 retirement.

The runners do not establish a cryptographic running-image hash or config
fingerprint; HIL-A01 cannot be PASS from the present firmware logs. A05 only
passes when a naturally occurring observable transaction correlates the same
EventKey across ACK and retirement. Outage/loss/replay stimulus is not part of
the observational runner. HIL-A06 is PARTIAL unless resource/reset-counter and
queue continuity evidence exists. Test-runner corrections also ensure a prior
motion FAIL cannot be hidden by a later operator abort, and only an all-case
physical PASS returns exit code zero.
