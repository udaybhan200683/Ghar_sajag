## D. Exact production changes

- `HubCheckpointCodec::encode_after_event` copies current reducer/coverage/
  activity/power state into a temporary heap runtime, executes the actual reducer
  and encodes its exact next state within existing bounds. The sizeable runtime
  object is not placed on the owner task stack. No live effect is emitted.
- `RuntimeStateStore::admission_workspace` checks identity quota and ordinal,
  reserves its reconstructible RAM index and computes identity growth/head plus
  replacement checkpoint workspace. `HubJournal`/outbox backend preflight checks
  current segment/slack/protected reserve, exact staged identity and combined
  filesystem free space, reserving the outbox index before durable preparation.
  `run_state_once` rejects before `prepare_identity` when these checks fail.
- One shared outbox position/charge function serves the preflight and actual
  append. Body/head/identity/checkpoint barrier ordering and Durable ACK timing
  remain unchanged. All schemas, NVS keys and partition tables are unchanged.
- `RecoveryState::recovery_report_bank_mask` is derived RAM metadata only.
  Report staging uses this plus the healthy independent witness. A witness ahead
  of selected NVS, epoch conflict, same-generation bank/digest conflict or all
  banks pinned cannot authorize a new staging write.

  proposed generation increases. Equal-generation NVS root conflicts compare
  authenticated plaintext, permitting different AEAD nonces for identical
  authority. Existing sanitized result categories and RPF00–08 remain.

## E. Admission and capacity correctness / limits

The immediate model rounds to the current 4-KiB allocation quantum:
identity frame `117 + canonical_key_bytes`, encrypted checkpoint
`checkpoint_bytes + 41`, event frame `54 + key_bytes + payload_bytes`, and a
replacement identity/event head where needed. Segment rollover slack and the
existing protected reserve are checked before writes. The S3 provider obtains
the same real filesystem usage through `esp_littlefs_info` for both stores.
Single-owner serialization holds this check through the admission writes.

Twelve ordinary reserve refusals leave no identity/body or transaction write;
two reboots and a protected event then succeed. A combined workspace fixture
rejects at one byte below 20,480 bytes and admits the exact same key at that
immediate rounded boundary. This is a deterministic sizing boundary, not a
commercial flash-capacity promise or physical allocator guarantee.

Interrupted operations retain at most one prepared owner at the next ordinal.
Thirteen fault cases preserve exact key/payload/local minute, reject another key
at that ordinal, reject conflicting immutable payload, suppress duplicate logical
effects on the second boot and admit a fresh third event. Existing queued/committed
sets are checked exactly; retired-through remains zero. No prepared-only abort
is implemented (GS148-ARCH-011 remains unimplemented). Unexpected real allocator
failure can retain that recoverable owner until exact retry; abandoned-transaction
disposition/whole-life escrow is not silently decided here.

The reducer bound fixture accepts 749 valid long-identity events, keeps a
65,462-byte readable checkpoint and rejects the next event before identity/body/
live reducer mutation. The selected checkpoint restores after reboot. No evidence
is truncated and no new maximum-count product contract is invented.

**Complete next engineering proposal, UNIMPLEMENTED pending approval:**

1. Failure boundary: first selected identity, complete encrypted body, absent
   first event head. Current v1 codec forbids ordinal zero and recovery correctly
   refuses any complete body when the authenticated head is missing. Filesystem
   errors returning failure after actual persistence make this reachable without
   a lost ACK. The current behavior is safe but blocks fresh-install availability.
2. Candidate correction: an authenticated native empty/genesis publication root
   selected and read back before the first body. Root binds storage/installation
   authority, format and zero highwater; it never represents an ACK. A complete
   first body behind that root can resume only its original selected identity.
   Missing/corrupt genesis still fails closed. Do not simply allow missing heads.
3. Compatibility: allowing zero in existing v1 is a behavioral format change
   because older readers reject it. Specify a versioned genesis representation,
   supported C3/S3 image/reader-writer and upgrade/automatic rollback matrix,
   ownership/key binding, original current-format activation and evidence before
   implementing. No legacy migration coordinator or arbitrary old-state repair
   follows from this proposal. Do not write irreversible new state before the
   supported rollback image understands it; otherwise adoption must remain
   disabled or use an explicitly approved fresh-install image contract.
4. Required fault matrix: empty-root write before/prefix/persist-then-fail,
   readback/barrier failure, first identity/body/head cuts, lost first ACK,
   conflicting first payload, removed/corrupt genesis, mismatched ownership/
   epoch/format, two reboots + fresh admission, and approved rollback images.
   Keep current missing-authority and security negative assertions mandatory.
5. Approval prerequisite: owning GS-148/GS-145 contract decision on genesis
   format and supported rollback, documented/versioned before dependent code.
   Exact on-device bytes/keys and adoption procedure need a reviewed design;
   there is no schema/key/partition modification in this package.

Proposed wire/storage design to review (not a chosen production format): retain
the current event-head logical file/key, and add a **v2, 116-byte genesis head**:
magic `GSHD` at 0–3, version 2 at 4, genesis flag 1 at 5, zero reserved bytes at
6–7, storage epoch u32 at 8–11, immutable installation/owner authority binding
32 bytes at 12–43, highwater u64 at 44–51 (zero for genesis), empty-body digest
32 bytes at 52–83, HMAC at 84–115. All integer endianness must match the current
outbox codec. HMAC covers 0–83 using a separately domain-labeled v2 publication
key derived from the approved installation storage key; reject zero/mismatched
epoch or authority and all unknown flags/reserved values. The authority binding
must come from the approved P3 installation manifest, never a mutable Node table
or simulated actor. D-F and supported key lifecycle therefore remain prerequisites.

Writer selects and reads back this native zero root before any first body write.
Reader accepts at most one exact complete staged body beyond it and resumes only
the selected identity/payload/context. Existing v1 nonzero heads retain their
meaning; after successful first publication the ordinary event-head encoding can
remain v1 if the approved compatibility matrix explicitly permits that transition.
Missing head on an already populated current-format store never creates genesis
automatically; corruption cannot be reclassified as fresh. Reboot recovery is
idempotent with either authenticated genesis or ordinary head.

Adoption needs a reader-first compatibility image before any writer creates v2;
both supported automatic-rollback images must understand v2 during the genesis
window. If the supported OTA mechanism cannot establish that prerequisite, keep
the writer disabled and restrict adoption to an explicitly approved fresh-install
baseline whose rollback pair is compatible. Do not erase existing stores, reset
epochs, silently migrate missing-head state or declare arbitrary old images
compatible. The on-device schema/key-domain change, installation authority and
reader/writer/rollback rollout require approval together before implementation.
