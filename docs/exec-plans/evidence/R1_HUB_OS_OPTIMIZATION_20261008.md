`-Os` materially improves 4 MiB: doubling the journal to 256 KiB could retain
slightly more OTA margin than the original 128 KiB/`-Og` layout. It still does
not fit 512 KiB with existing two-slot alignment, even before firmware growth,
and does not fix prior 256 KiB capacity failures. The 72-hour target, approved
event volume/reserve policy, sustainable reclamation and integrated cloud/storage/
FOTA growth remain unqualified. No partition/hardware requirement is locked.

Retain the 8 MiB classic ESP32 evaluation from
[capacity evidence](R1_FLASH_OTA_CAPACITY_DECISION_20261008.md): more flash is a
practical alternative to risky feature/refactor cuts for the demonstrated larger
storage envelope. This is an engineering recommendation; actual landed BOM and
module/physical/OTA/RAM qualification remain necessary. No S3 migration/purchase.

**Single highest-value next action:** implement and prove the bounded SDK NVS
protected-workspace restoration/reclamation step already identified by the storage
capacity evidence, before production storage integration. Keep `-Os` as the
measured build candidate and require hardware timing/stack/FOTA validation before
production activation. Do not divert into these five optional optimizations now.
